## Implemented scope

- One reviewed `media_volume.set` command, integer 0–70%. Multi-step commands, brightness and application launches remain previews. Web and iOS retain their existing preview behavior.
- Explicit device enrollment uses the existing HTTPS account/device security flow and device-bound P-256 key. Setup never silently replaces a different account/origin binding. The normal account bearer, device-management token, simulation scope and new `assistant:volume` scope are distinct.
- New volume endpoints live under `/api/v1/assistant/volume`: session creation, task creation/read/cancel, authorization challenge/proof, one-use claim, and receipt challenge/proof. Existing simulation contracts and execution behavior are preserved. Wire declarations are added to both clients without reformatting their existing declarations.
- Security schema v3 adds only volume sessions and a volume task ledger. Every mutation revalidates parent login, management session, enrolled Android device, public key, origin and execution session inside the write transaction. Task IDs, exact percentage, revision, challenge, expiry, device signature and permit hash are bound together. A claim consumes the permit atomically; concurrent/repeated claims fail. Task idempotency tombstones survive execution-session cleanup.
- The native worker, not JavaScript, obtains the real scope, creates the task, displays the exact transaction, signs proofs, consumes the claim over platform-validated HTTPS and reports the result. Network paths are compiled, redirects are refused, responses are bounded, deadlines/cancellation are checked, and ambiguous requests are never retried. JavaScript cannot inject an executable server response or call an arbitrary stream/OS command.
- The native dialog shows the requested percentage and the representable Android stream step. Its approval rejects obscured/partially obscured touches. Foreground, resumed activity, passcode/unlock state, immutable binding and expiry are rechecked before dispatch. React Native modal windows are supported without assuming that the host activity window has focus.
- A bounded, app-private `noBackupFilesDir` journal is synchronously committed before claim/dispatch. A durable unknown marker precedes any possible effect; successful readback updates it. Existing journal entries are never dispatched again. Key deletion cancels pending work and removes that installation's journal. Background, close, Clear/cancel, account changes and module teardown invalidate the pending operation. Bridge order captures cancellation ownership before the worker starts.
- Only `AudioManager.STREAM_MUSIC` with flags `0` is set. Integer division rounds down, never above the approved percentage. Unsupported minima, fixed-volume devices, changed stream limits and OS restrictions fail closed or report uncertainty. Android safe-volume and Do Not Disturb restrictions are not bypassed. Readback verifies the actual stream index; a 50% request on a 15-step device reports step 7 / approximately 46%, not an invented exact 50%.
- Outcomes distinguish verified, failed, cancelled and `outcome_unknown`. A locally verified result with an unacknowledged server receipt says so explicitly. Interrupted work is not automatically replayed. Receipt evidence is signed, device-reported readback, not independent server observation of hardware.

## Data and retention

No command text, transcript or audio is sent to this protocol or stored in its ledgers. Server rows contain bounded volume arguments, account/device/session identifiers, public binding/challenge metadata, state and stream-index evidence. Bearers and permits are stored as hashes; native journals contain task/claim IDs, numeric volume fields and outcome, never credentials, private keys or recordings. Task cleanup is bounded and opportunistic on new allocations after seven days; it is not a guaranteed timed deletion service. Native storage is capped at 1,024 directory entries and fails closed when full; deleting the device key purges its journal. Operational retention, backup/restore and deletion acceptance remain release gates.
