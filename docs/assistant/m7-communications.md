From Assistant, opt into AI planning and submit a reviewed example by typing or the existing on-device microphone. The public-only router opens Calls and messages, obtains a non-executing proposal, asks you to select one recipient locally and opens exact native approval. Approving opens the phone interface; its Call/Send control remains yours. The private manual form remains available without AI.

## Architecture and privacy

- Shared `communications.ts` validates an exact plain-data draft and returns a fresh copy. It requires one visible international number with `+`/country code (8-15 digits), never guesses a country, rejects extensions/service codes/URI syntax, and bounds message text to 1000 UTF-16 code units. Hidden controls, bidi overrides and malformed surrogates are rejected. Text is not URL-encoded into a remote link or written into a persistent Contexify draft.
- `CommunicationManager` owns the private fields only for this screen. Close, account changes and backgrounding clear them and cancel pending work. A new explicit Android contact-picker selection may return one selected number after its separate OS activity; it grants no call/send authority. Native selection times out after 60 seconds. No whole-contact/name list is fetched or uploaded. A national-only selected number must be completed with its country code manually before a handoff.
- `createCommunicationCompanion` supports missing/older native binaries, serializes requests, freezes the draft before awaiting, binds cleanup to a request ID, and ignores late results after disposal/account/lifecycle changes. There is no HTTP client, persistence port, general URL or execution signer in this service.
- The existing native `AssistantPlatform` module is extended with a narrow Android implementation and optional bridge methods. Android is restricted to the separate test package plus its compiled shared execution gate. iOS retains the compiled isolated platform gate. No per-command environment switch or third-party native dependency is introduced. Production execution flags remain disabled; an OTA or Expo Go cannot supply these native implementations.
- These are **user-owned OS presentation surfaces**, like the existing Calendar editor, not server-authorized action adapters. A cached profile or `user_id` is not treated as authority to call/send. UI sign-in controls entry visibility; the security boundary for this scope is exact native review followed by the user's OS Call/Send choice. Existing server-bound proof/claim/receipt protocols remain required for their existing execution adapters and are neither reused as a generic signer nor bypassed to assert an automatic communications effect.
- Native code independently validates the payload, allows only compiled dial/SMS templates, requires an unlocked foreground app, permits one request at a time and requires fresh exact approval. Approval/picker expiry is bounded using a monotonic clock; no stale approval is restored. Native bodies are transient, not recorded as receipts. This does not claim immediate erasure of every OS/runtime memory copy.
- Already opened external phone interfaces, saved drafts, messages and call history belong to the receiving app. Contexify cannot retract them on cancellation/logout. The native and private-screen disclosures explain this and possible charges. These features are not an emergency service.

### Command pipeline and processing boundary

- `public-command-scope.ts` admits 12 reviewed M7 examples and the existing 22 public settings examples before any mobile or browser assistant AI traffic. The list authorizes data egress; it does not map phrases to actions. Gemini still interprets the command. Command case/spacing may vary; quoted message contents retain exact case/bytes. Backend admission independently checks M7 membership, even with a fake or misconfigured provider.
- `POST /api/v1/assistant/planning/communication-proposals` reuses the existing authenticated planning grant, synthetic-data consent, CSRF/session/device checks, shared rate/admission budgets, provider quota cooldown, concurrency bound, bounded schema repair, disconnect handling and late authorization recheck. The Flash-Lite pin, shared 30/day reviewed-test cap and disabled paid billing remain unchanged. No model request is made just by opening the screen.
- The separate versioned communication schema permits only dial/SMS presentation, `local_picker` and bounded message text (or null for local completion). It contains no recipient identity/number, execution permit, contact list or approval. Settings proposals keep their existing wire shape. Both server and client reject recipient/authority injection, invalid data, mismatched ownership, expired proposals and model message content absent from the approved input. Raw provider output is not forwarded to another planner or executed.
- The existing planner/grant lifecycle is shared through `createProposalPlanner`; no duplicate auth signer or model SDK is placed in the client. Main-screen consent transfer is fresh, one-shot and account-bound. AI input/consent and private fields clear on background/account/Close. The explicit Android picker exception may finish its already-prepared request through fresh native review after selection; it cannot call/send automatically or begin another cloud request.
- Native `openPlannedCommunication` bounds approval to the earlier of the proposal deadline and the existing 60-second review limit. Native code independently converts that bound to a monotonic deadline and rechecks it before presentation. An older binary without this method blocks the AI flow before any cloud request. The legacy private manual composer remains compatible. A completed proposal is transient; no new SQL table, migration, persistent conversation or automatic retry is added.

### Android adapter

`ACTION_PICK` with `Phone.CONTENT_TYPE` requests one phone property. Only the returned Contacts-provider `content:` phone-item URI is queried, with a projection containing just the selected number; no persistent grant or `READ_CONTACTS` is requested. Late activity results use distinct native request codes, selected private data returns only when foreground/unlocked, and cancellation closes only that request's picker where possible.

Phone uses `ACTION_DIAL`, never `ACTION_CALL`. Text uses `ACTION_SENDTO`/`smsto:`, never `SmsManager`. The destination is the OS-configured default dialer/SMS app. Its exported/enabled component, version/update time and signing identity are captured before native approval and rechecked before explicit-component launch. An unavailable/changed handler fails safely; there is no browser fallback, arbitrary package or invisible automatic retry. A successful launch means only `handoff_requested`, not a connected call, sent SMS or delivery.

The module manifest adds only three narrow intent queries. It adds no permission, exported component, call-log access, phone-state access, contact read, `CALL_PHONE`, `SEND_SMS`, package enumeration, accessibility automation or overlay.

### iPhone adapter — source only; Apple checks deferred

`CNContactPickerViewController` selects a single phone property without a Contacts-store read grant. `MFMessageComposeViewController` is offered only when the device reports text messaging support. It presents one reviewed recipient and the reviewed body, then the user may edit/send/cancel there. Its delegate reports `sent_in_composer`, `cancelled_in_composer`, `failed` or `outcome_unknown`; a Send report is not recipient delivery. Cancellation may leave an OS-owned draft.

The fixed `tel:` URL contains only the validated number. iOS's phone interface supplies the final call confirmation; opening is not proof of connection. All API use remains in an enabled, unlocked foreground presentation. Calendar and communication presentations cannot overlap. Background/lock/Close invalidates pending presentation; native request IDs prevent one component from dismissing a newer component's editor. Picker/approval is bounded to 60 seconds; the user-owned SMS editor is bounded to five minutes here and is not silently restored.

ContactsUI and MessageUI are Apple system frameworks linked by the existing pod. No Contacts read purpose string, private contact store, SMS entitlement, third-party URL-query entitlement or new Apple paid capability is requested by this adapter. Actual Swift/pod/API compatibility, signing, OS presentation and delegate/lifecycle behavior still need the borrowed Mac/iPhone batch. Refresh the source transfer for that build: the old M6 source ZIP predates M7.

The iOS config plugin declares only the built-in `tel` scheme query needed by `canOpenURL` in the enabled test build. It preserves app-owned schemes, avoids duplicate entries and removes its own added query on a disabled rebuild. This is availability discovery, not call permission or a third-party connector grant.
