# Phase 3 implementation checkpoint

The next-step instruction authorizes foreground voice and editable command-preview source work from clean commit `4d4b86d`. Phase 1A/2 native compilation, physical-device and operational gates remain open. No deployment, provider processing, real action executor or wake/background listening is authorized.

## Scope

- Add a separate, visible Assistant preview in web and mobile, with editable text/transcript, explicit review and supported-command examples. Nothing is submitted to chat, the assistant ledger or a provider.
- Add shared bounded voice-session state with explicit microphone consent, transcript correction, cancellation, stale-callback protection and memory-only state cleared on background/close/account change.
- Android-first native on-device recognition and local-voice playback; restricted browser adapter accepting only explicit local processing. Unsupported devices/browsers/iOS retain text input. iOS native extensions remain Phase 5.
- Native/browser voice controls remain disabled by default until build/device privacy gates pass. No silent network fallback, audio file recording, transcript logging, cloud integration or automatic command execution.
- Verify with synthetic adapters, unit/regression/type/contract checks. Physical microphone, interruption, privacy and latency tests remain separate release gates.

## Implemented source

- Web: **Assistant preview** in the sidebar (including its collapsed icon). Mobile: header **Conversation options** (three dots) → **Assistant preview**. The preview is separate from chat, uses existing themes and clears its session when the account changes. Native modals keep existing chat-header and keyboard geometry intact.
- Text commands become bounded, typed, ordered review steps. Editing invalidates the previous preview. There is no Execute button, provider call, ledger submission or OS action. Platform-only prototypes are labeled as unavailable for execution in a browser/unsupported platform. Own-app opening is still only a proposed catalog entry.
- Shared session controller: explicit microphone consent, visible starting/listening/processing states, editable final transcript, optional reading of reviewed public labels, 30-second capture/playback cap, five-second Stop deadline, three-second availability deadline and stale-callback rejection. Clearing purges text, preview, interim words and consent. Recognition never starts automatically from a transcript, TTS, restore or background event.
- Browser: `SpeechRecognition.available({langs:["en-US"],processLocally:true})` must report `available`; the instance must expose and accept `processLocally=true`. No legacy `webkitSpeechRecognition`, server-backed mode or language-pack installation is used. Speech synthesis chooses an installed English `localService` voice explicitly. Unsupported/insecure/nonforeground contexts preserve typing. [MDN local recognition](https://developer.mozilla.org/en-US/docs/Web/API/SpeechRecognition/available_static), [local speech voices](https://developer.mozilla.org/en-US/docs/Web/API/SpeechSynthesisVoice/localService).
- Android: separate `AssistantVoice` Expo module; recognition uses `createOnDeviceSpeechRecognizer` on API 31+ only. It requires a resumed unlocked activity and just-in-time microphone permission, with audio-focus, pause/destroy, request-ID and timeout guards. Engine buffers are discarded; no recorder/file/network API is used. TTS rejects network-required or not-installed voices before selecting one. [Android recognition API](https://developer.android.com/reference/android/speech/SpeechRecognizer), [voice installation/network metadata](https://developer.android.com/reference/android/speech/tts/TextToSpeech.Engine#KEY_FEATURE_NOT_INSTALLED).
- Speech and Stop/cancel events carry request IDs, so stale native callbacks cannot overwrite text or cancel a newer operation. Android activity-resume checks support React Native modal windows; focus loss/audio interruption behavior still needs hardware verification. Permission dialogs may interrupt and cancel a request; returning to the app never automatically resumes capture.
- iOS and mobile web retain text preview. iOS native speech remains the later extension phase; no new iOS speech permissions or framework is introduced in this batch.
- `VITE_ASSISTANT_VOICE_ENABLED` and `EXPO_PUBLIC_ASSISTANT_VOICE_ENABLED` are opt-in and default to false when absent. Neither was enabled here. The preview also requires signed-in UI state before exposing voice; OS permission and native lifetime checks remain independent, and only Phase 2 server/native authorization could grant a future action. All server assistant flags remain unchanged/off.
- Native changes bump app/package/lockfile root versions to **1.4.0**, matching the existing app-version runtime policy. No new third-party dependency, app binary, OTA, deployment or configured backend/data access was introduced.
